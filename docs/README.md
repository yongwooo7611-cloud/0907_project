# 개인 프로필 페이지 개발 문서

## 1. 프로젝트 개요

HTML, CSS, JavaScript를 사용하여 개인의 소개, 기술, 경력 및 작업물을 보여주는 반응형 프로필 페이지를 만든다.

- 프로젝트 유형: 정적 웹 페이지
- 대상 사용자: 채용 담당자, 협업 파트너, 방문자
- 주요 목표: 개인 정보와 작업물을 명확하고 보기 좋게 전달
- 개발 위치: 프로젝트 루트(GitHub Pages 배포 구조)

## 2. 기술 구성

| 기술 | 역할 |
| --- | --- |
| HTML5 | 페이지 구조와 콘텐츠 작성 |
| CSS3 | 레이아웃, 디자인, 반응형 화면 구성 |
| JavaScript | 메뉴, 테마 전환, 스크롤 효과 등 사용자 상호작용 |

초기 버전에서는 별도의 프레임워크나 빌드 도구를 사용하지 않는다.

## 3. 페이지 구성

### 헤더

- 이름 또는 로고
- 소개, 기술, 프로젝트, 경력, 연락처로 이동하는 내비게이션
- 모바일 화면용 메뉴 버튼
- 선택 사항: 라이트/다크 테마 전환 버튼

### 메인 소개(Hero)

- 프로필 사진 또는 대표 이미지
- 이름
- 직무 또는 한 줄 소개
- 짧은 자기소개
- 프로젝트 보기 및 연락하기 버튼

### 자기소개(About)

- 개인 소개
- 관심 분야와 목표
- 현재 하고 있는 일 또는 학습 내용

### 기술(Skills)

- 사용 가능한 기술 목록
- 기술별 숙련도는 초급, 중급, 고급 등의 텍스트로 표현
- 예: HTML, CSS, JavaScript, Git

### 프로젝트(Projects)

각 프로젝트 카드는 다음 정보를 포함한다.

- 프로젝트 이름
- 대표 이미지
- 간단한 설명
- 사용 기술
- 데모 링크
- 소스 코드 링크

### 경력 및 활동(Experience)

- 회사, 학교 또는 활동명
- 역할
- 활동 기간
- 주요 업무 및 성과

경력이 없다면 학습 과정, 교육, 자격증 또는 개인 활동으로 대체할 수 있다.

### 연락처(Contact)

- 이메일
- GitHub 및 소셜 링크
- 연락하기 버튼 또는 간단한 문의 폼

백엔드 연동 전에는 문의 폼이 실제로 전송되는 것처럼 표시하지 않는다. 초기 버전에서는 이메일 링크(`mailto:`) 사용을 권장한다.

### 푸터

- 저작권 문구
- 현재 연도를 JavaScript로 자동 표시
- 페이지 상단으로 이동하는 링크

## 4. 프론트엔드 파일 구조

```text
프로젝트 루트/
├── index.html
├── about.html
├── skills.html
├── projects.html
├── css/
│   └── style.css
├── js/
│   └── main.js
└── assets/
    ├── images/
    └── icons/
```

파일별 역할:

- `index.html`: 전체 콘텐츠와 시맨틱 구조
- `css/style.css`: 공통 스타일, 컴포넌트, 반응형 스타일
- `js/main.js`: 메뉴와 테마 등 사용자 상호작용
- `assets/images`: 프로필 및 프로젝트 이미지
- `assets/icons`: 필요한 로컬 아이콘

## 5. HTML 작성 기준

- `header`, `nav`, `main`, `section`, `article`, `footer` 등 시맨틱 태그를 사용한다.
- 각 섹션에는 고유한 `id`를 지정한다.
- 제목은 `h1`부터 순서를 지켜 작성한다.
- 이미지에는 내용을 설명하는 `alt` 속성을 넣는다.
- 외부 링크를 새 창으로 열 경우 `rel="noopener noreferrer"`를 함께 사용한다.
- 버튼과 링크는 실제 역할에 맞는 요소를 사용한다.

권장 섹션 ID:

```text
#home
#about
#skills
#projects
#experience
#contact
```

## 6. CSS 디자인 기준

### 기본 방향

- 콘텐츠 최대 너비: 약 `1100px`
- 본문은 읽기 쉬운 글자 크기와 줄 간격 유지
- 색상, 여백, 모서리 크기는 CSS 변수로 관리
- 카드와 버튼 스타일을 일관되게 적용
- 마우스 없이도 현재 포커스 위치를 확인할 수 있게 표시

CSS 변수 예시:

```css
:root {
  --color-primary: #4f46e5;
  --color-background: #ffffff;
  --color-surface: #f8fafc;
  --color-text: #0f172a;
  --color-muted: #64748b;
  --border-radius: 12px;
  --content-width: 1100px;
}
```

### 반응형 기준

- 모바일 우선으로 작성한다.
- 작은 화면에서는 내비게이션을 접을 수 있게 한다.
- 프로젝트 카드는 모바일 1열, 태블릿 2열, 데스크톱 3열을 기본으로 한다.
- 이미지가 컨테이너 밖으로 넘치지 않도록 한다.
- 권장 분기점: `768px`, `1024px`

## 7. JavaScript 기능 범위

초기 버전에 포함할 기능:

1. 모바일 내비게이션 열기 및 닫기
2. 내비게이션 선택 시 해당 섹션으로 이동
3. 메뉴 선택 후 모바일 내비게이션 자동 닫기
4. 푸터의 현재 연도 자동 표시

선택 기능:

- 라이트/다크 테마 전환 및 선택값 저장
- 현재 보고 있는 섹션에 맞춰 메뉴 강조
- 요소가 화면에 들어올 때 가벼운 등장 효과
- 프로젝트 목록 필터링

JavaScript가 동작하지 않더라도 핵심 콘텐츠와 링크는 사용할 수 있어야 한다.

## 8. 콘텐츠 준비 목록

개발 전에 다음 정보를 준비한다.

- 표시할 이름
- 직무 또는 관심 분야
- 자기소개 문장
- 프로필 이미지
- 기술 목록
- 프로젝트별 이름, 설명, 이미지, 기술, 링크
- 경력 또는 활동 이력
- 이메일, GitHub 등 연락처

개인 전화번호, 집 주소와 같은 민감한 정보는 공개 페이지에 넣지 않는다.

## 9. 접근성 및 품질 기준

- 키보드만으로 메뉴와 링크를 사용할 수 있어야 한다.
- 텍스트와 배경의 명도 대비를 충분히 확보한다.
- 모든 입력 요소에는 연결된 `label`을 제공한다.
- 애니메이션은 과도하게 사용하지 않는다.
- `prefers-reduced-motion` 설정 사용자를 고려한다.
- 모바일, 태블릿, 데스크톱 화면에서 레이아웃을 확인한다.
- 브라우저 콘솔에 오류가 없어야 한다.

## 10. 개발 순서

1. 실제 프로필 콘텐츠를 준비한다.
2. 프로젝트 루트에 기본 파일과 하위 폴더를 만든다.
3. HTML로 모든 섹션과 콘텐츠를 작성한다.
4. CSS로 모바일 화면부터 디자인한다.
5. 데스크톱 반응형 레이아웃을 추가한다.
6. JavaScript 상호작용을 구현한다.
7. 접근성, 링크, 반응형 화면 및 콘솔 오류를 점검한다.

## 11. 완료 기준

- [ ] 모든 필수 섹션이 표시된다.
- [ ] 내비게이션 링크가 올바른 섹션으로 이동한다.
- [ ] 모바일 메뉴가 정상적으로 작동한다.
- [ ] 프로젝트 링크와 연락처가 유효하다.
- [ ] 이미지 대체 텍스트가 작성되어 있다.
- [ ] 화면 너비가 달라져도 가로 스크롤이 생기지 않는다.
- [ ] 키보드로 주요 기능을 사용할 수 있다.
- [ ] JavaScript 오류가 발생하지 않는다.
- [ ] 오탈자와 임시 콘텐츠를 제거했다.
